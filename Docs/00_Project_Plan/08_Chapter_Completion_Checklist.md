# 08 Chapter Completion Checklist

## الهدف

هذه القائمة تحدد متى نعتبر أي فصل في المرجع مكتملًا وجاهزًا للاعتماد.

لا يكفي أن يكون الفصل طويلًا. يجب أن يكون صحيحًا، منظمًا، عمليًا، ومفيدًا للمبتدئ والمتوسط.

## Checklist عام لكل فصل

- [ ] الفصل يحتوي على `README.md` واضح.
- [ ] هدف الفصل مكتوب بوضوح.
- [ ] الملفات داخل الفصل مرتبة بأرقام واضحة.
- [ ] يوجد ترتيب قراءة مقترح.
- [ ] المصطلحات الأساسية مشروحة قبل استخدامها بكثافة.
- [ ] المحتوى مبني على Godot 4.x.
- [ ] لا يوجد خلط بين Godot 3 و Godot 4.
- [ ] لا يوجد خلط بين Node و Resource.
- [ ] لا يوجد خلط بين الرسم والتصادم.
- [ ] أي Node مذكور تم التحقق من وراثته.
- [ ] أي Node لا يرث من `Node2D` لكنه يستخدم في 2D تم توضيح ذلك.
- [ ] توجد أمثلة عملية واضحة.
- [ ] توجد جداول مقارنة عند الحاجة.
- [ ] توجد أمثلة Node Tree عند شرح التركيب.
- [ ] توجد أخطاء شائعة مع التصحيح.
- [ ] توجد خلاصة عملية في نهاية الملفات المهمة.
- [ ] توجد مصادر رسمية في نهاية الملفات التعليمية.

## Checklist لملف شرح Node واحد

- [ ] اسم Node واضح في العنوان.
- [ ] التعريف المختصر موجود.
- [ ] شجرة الوراثة موجودة أو موضحة.
- [ ] الوظيفة الأساسية مشروحة.
- [ ] متى يستخدم Node موضح.
- [ ] متى لا يستخدم Node موضح.
- [ ] هل يحتاج Collision موضح.
- [ ] أفضل الأبناء أو الأبناء الشائعون مذكورون.
- [ ] مثال Node Tree موجود.
- [ ] مثال عملي من لعبة موجود.
- [ ] أخطاء شائعة موجودة.
- [ ] مقارنة مع Nodes مشابهة إذا كان ذلك مفيدًا.
- [ ] خلاصة سريعة موجودة.
- [ ] مصادر رسمية موجودة.

## Checklist لملف المقارنة

- [ ] يوجد جدول مقارنة سريع.
- [ ] معايير المقارنة واضحة.
- [ ] لا توجد أحكام مطلقة غير دقيقة.
- [ ] الحالات العملية موضحة.
- [ ] الفرق بين “ممكن” و “مناسب” واضح.
- [ ] توجد أمثلة اختيار صحيحة وخاطئة.
- [ ] توجد خلاصة قرار في النهاية.

## Checklist للفصول التي تحتوي Collision

- [ ] تم توضيح الفرق بين `CollisionShape2D` كـ Node و Shape Resources.
- [ ] تم شرح متى يستخدم كل Shape.
- [ ] تم توضيح أن `Sprite2D` لا يصنع Collision وحده.
- [ ] تم توضيح أن `Area2D` يكشف ولا يعمل كأرض صلبة غالبًا.
- [ ] تم تقديم أمثلة Player, Coin, Ground أو ما يعادلها.

## Checklist للفصول التي تحتوي Physics

- [ ] تم شرح `CharacterBody2D`.
- [ ] تم شرح `StaticBody2D`.
- [ ] تم شرح `RigidBody2D`.
- [ ] تم شرح `AnimatableBody2D`.
- [ ] تم شرح `Area2D`.
- [ ] تم تقديم جدول: يتحرك؟ يتأثر بالجاذبية؟ يستخدم للاعب؟ يستخدم للأرض؟ يتحكم به المحرك؟
- [ ] تم توضيح لماذا لا يستخدم `StaticBody2D` عادة للاعب.
- [ ] تم توضيح لماذا لا يستخدم `Area2D` كأرض.

## Checklist للفصول العملية

- [ ] يوجد مثال Player Tree.
- [ ] يوجد مثال Enemy Tree.
- [ ] يوجد مثال Coin Tree.
- [ ] يوجد مثال Door Tree.
- [ ] يوجد مثال Bullet Tree.
- [ ] يوجد شرح لماذا كل Node موجود في الشجرة.
- [ ] يوجد شرح ماذا يحدث لو حذفنا Node مهم.
- [ ] توجد بدائل عند اختلاف نوع اللعبة.

## تعريف “مكتمل”

الفصل يعتبر مكتملًا عندما:

1. يغطي النطاق المتفق عليه.
2. يمر على هذه القائمة بدون نقاط ناقصة مهمة.
3. يوافق المستخدم على محتواه.
4. يتم رفعه إلى GitHub.

## مبدأ الجودة

الفصل القصير الصحيح أفضل من فصل طويل مليء بالخلط. لكن هدف هذا المشروع هو التفصيل العميق، لذلك نريد محتوى طويلًا عندما يكون الطول مفيدًا ومنظمًا.
