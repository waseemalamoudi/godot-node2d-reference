# 01 — ما هو Node؟

## 1. التعريف المختصر

`Node` هو وحدة البناء الأساسية في Godot. أي شيء تقريبًا داخل المشهد يكون Node أو مجموعة Nodes: لاعب، كاميرا، صورة، صوت، مؤقت، جسم فيزيائي، أو عنصر واجهة.

النقطة المهمة: ليس كل Node يظهر على الشاشة، وليس كل Node لديه تصادم أو فيزياء. بعض Nodes تنظيمية أو خدمية فقط.

## 2. الفكرة الأساسية

Godot يبني اللعبة على شكل شجرة:

```text
Root Node
├── Child Node
├── Child Node
└── Child Node
```

كل Node يمكن أن يحتوي أبناء. هذه العلاقة تنتج ما يسمى `Scene Tree` أثناء التشغيل، وما يسمى `Scene` عندما تُحفظ هذه الشجرة كملف.

## 3. أمثلة على Nodes مختلفة

| Node | نوعه | هل يظهر بصريًا؟ | وظيفته |
|---|---|---:|---|
| `Sprite2D` | رسم | نعم | عرض صورة 2D. |
| `Camera2D` | كاميرا | لا كصورة، لكنه يؤثر على الرؤية | تحديد ما يراه اللاعب. |
| `CharacterBody2D` | فيزياء/حركة | ليس بنفسه غالبًا | جسم مناسب للاعب أو عدو يتحرك بالكود. |
| `CollisionShape2D` | تصادم | يظهر في المحرر غالبًا وليس كلاعب | يحدد شكل التصادم. |
| `Timer` | مساعد | لا | تنفيذ حدث بعد وقت أو بتكرار. |
| `AudioStreamPlayer2D` | صوت | لا | تشغيل صوت في مكان داخل عالم 2D. |

## 4. Node لا تعني دائمًا شيئًا مرئيًا

خطأ شائع عند المبتدئ أن يظن أن كل Node يجب أن يكون له صورة. هذا غير صحيح.

مثال:

```text
Enemy (CharacterBody2D)
├── AnimatedSprite2D       ← مرئي
├── CollisionShape2D       ← تصادم
├── Timer                  ← غير مرئي
└── AudioStreamPlayer2D    ← غير مرئي لكنه يصدر صوتًا
```

كل هذه Nodes، لكن وظائفها مختلفة.

## 5. هل كل Node تصلح Root؟

تقنيًا، كثير من Nodes يمكن أن تكون Root لمشهد. لكن عمليًا يجب اختيار Root حسب وظيفة المشهد.

| المشهد | Root مناسب | لماذا؟ |
|---|---|---|
| مشهد لعبة كامل | `Node2D` | ينظم عناصر عالم 2D. |
| لاعب | `CharacterBody2D` | يحتاج حركة وتصادم. |
| عملة | `Area2D` | تحتاج كشف لمس فقط. |
| واجهة | `Control` | تحتاج نظام UI وليس عالم 2D. |
| صورة زخرفية بسيطة | `Sprite2D` أو `Node2D` | حسب هل تحتاج تجميع عناصر أم صورة فقط. |

## 6. مثال عملي

```text
Player (CharacterBody2D)
├── AnimatedSprite2D
├── CollisionShape2D
└── Camera2D
```

هنا:

- `Player` هو Root Node للمشهد.
- `AnimatedSprite2D` يعرض شكل اللاعب.
- `CollisionShape2D` يحدد تصادم اللاعب.
- `Camera2D` تتبع اللاعب إذا كانت مفعلة.

## 7. مثال GDScript بسيط

```gdscript
func _ready() -> void:
    var marker := Node2D.new()
    marker.name = "SpawnPoint"
    add_child(marker)
```

هذا ينشئ Node جديدًا ويضيفه كابن للنود الحالية.

## 8. أخطاء شائعة

| الخطأ | لماذا هو خطأ؟ | التصحيح |
|---|---|---|
| أظن أن Node تعني صورة | بعض Nodes غير مرئية. | اسأل دائمًا: ما وظيفة هذا Node؟ |
| أضع كل شيء داخل مشهد واحد ضخم | يصعب الصيانة وإعادة الاستخدام. | قسم اللعبة إلى Scenes صغيرة. |
| أختار Root عشوائيًا | يؤدي لتركيب غير مناسب. | اختر Root حسب وظيفة المشهد. |
| أستخدم `Sprite2D` كلاعب كامل | هو صورة فقط. | استخدم `CharacterBody2D` للاعب المتحرك. |

## 9. خلاصة سريعة

`Node` هو لبنة البناء. لا تحكم على Node من اسمه فقط أو من كونه ظاهرًا. اسأل دائمًا: هل هذا النود للرسم؟ للحركة؟ للتصادم؟ للصوت؟ للتنظيم؟ ثم اختر مكانه داخل الشجرة بناءً على وظيفته.
